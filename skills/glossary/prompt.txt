`inputs/` 안의 PDF와 transcript(.txt) 파일들로부터 체계적인 도메인 용어집을
생성해 `outputs/glossary.md`로 저장합니다.

# 사전 처리

- PDF들: `python scripts/extract_pdf.py inputs/*.pdf -o _extracted`
  결과: `_extracted/<원본이름>.txt` (페이지 구분 포함)
- txt들: `python scripts/strip_tags.py inputs/*.txt -o _stripped`
  `<text>` 블록만 남긴 사본 생성. 태그 없으면 원본 그대로 복사.

사전 처리 후의 `_extracted/*.txt` + `_stripped/*.txt`가 용어 추출 대상.

# 방법 (map → reduce)

## 1단계: Map — per-file 용어 리스트 (간이 체크리스트용)

각 사전처리 텍스트 파일마다, 그 파일에 등장하는 **도메인 전문 용어**를 뽑아
`_terms/<원본이름>.txt`에 **한 줄에 하나씩 용어명만** 기록 (정의 불필요).

- 일반어/일상어/접속사 등 제외
- 전문 용어, 고유명사, 핵심 개념만
- 한글 용어는 한글, 영문 용어는 영문. 병기 필요 시 `한글(English)` 형태
- 이 per-file 리스트는 최종 문서 작성 후 **누락 검증용 체크리스트**로 씁니다

## 2단계: Reduce — 통합 용어집 작성

`_terms/`의 모든 용어를 모은 뒤, 체계적으로 재구성해 `outputs/glossary.md`로 저장.

### 구성 원칙

1. **테마 대분류** (3~6개): 용어 전체를 훑어보고 자연스러운 주제로 묶음
2. **하위 그룹**: 각 테마 아래에 연관성 높은 용어들을 그룹핑
3. **용어 정의**: `- **용어**: 정의` 형태. 강의 맥락 기반으로 간결하게. 출처 표기 불필요
4. **통합 설명 문단**: 각 하위 그룹 끝에 1~3문장의 통합 설명을 추가. 해당 그룹 용어들이 강의 맥락에서 어떻게 서로 연결되어 작동/상호작용하는지를 **문맥적으로 엮어** 설명. 예:

   > 위 용어들은 TCA 회로의 산화 단계에서 사용된다. X가 Y를 촉매하여 Z를 생성하고, Z는 다시 W의 기질로 작동하여 전체 사이클이 유지된다.

   표현은 더 정제해서 쓸 것. 단순 나열이 아니라 흐름이 드러나도록.

### 출력 형식 (Markdown)

    # 용어집

    ## <테마 1 이름>

    ### <하위 그룹 1>

    - **용어 A**: 정의...
    - **용어 B**: 정의...
    - **용어 C**: 정의...

    [통합 설명 문단]

    ### <하위 그룹 2>
    ...

    ## <테마 2 이름>
    ...

## 3단계: 검증

`outputs/glossary.md` 작성 완료 후, `_terms/` 안의 모든 용어가 최종 문서에
**빠짐없이** 포함됐는지 교차 확인. 누락된 용어가 있으면 가장 적절한 테마/하위
그룹에 추가하고 통합 설명도 보완.

# 언어

모든 서술은 한국어로.
